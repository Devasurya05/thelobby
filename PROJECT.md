# The Lobby: PROJECT.md (handoff overview)

Last updated: 2026-11-11

## What this is
A group-trip app: people pick beds/rooms in a live lobby without clashing (row locking + 2-minute holds), then share documents in a private vault (private S3 bucket, 60-second pre-signed links, roles) that deletes itself when the trip ends.

Design principles: no double booking, temporary holds, one source of truth, right access for the right person, private data does not live forever, everything is logged.

## Stack
- PHP 8.4.27 (winget, includes PHP2Shell fix), Laravel 13.42, Blade, jQuery (CDN, polling ~2s)
- MySQL 8.4.9 local (Oracle Community Server); AWS RDS MySQL in production
- AWS (Free plan only, never upgrade): EC2, RDS, S3, IAM. Region: ap-south-1 (Mumbai), decided 2026-11-11; S3, RDS and EC2 must all be in it
- Composer 2.11.2 (composer.phar, checksum verified)

## Environment (Windows, PowerShell)
- MySQL runs as a plain process (no service): `powershell -File scripts\start-mysql.ps1` after every reboot. Data directory lives outside the project folder. DBs: `thelobby`, `thelobby_test`; user `thelobby`. Passwords only in `.env` (never committed).
- `.env` already points Laravel at local MySQL; `APP_NAME="The Lobby"`.
- Default users/password_reset tables were removed (we use `members`). `sessions`, `cache`, `jobs` tables kept. config/auth.php still mentions the deleted User model (harmless, unused).

## Decisions log (append only)
- 2026-11-11: Name is "The Lobby". Repo name `thelobby`.
- 2026-11-11: Real MySQL 8.4 (not XAMPP/MariaDB), same family as AWS RDS MySQL.
- 2026-11-11: PHP via winget zip build (thread-safe, no installer), php.ini made from php.ini-development with needed extensions enabled. Composer via checksum-verified composer.phar.
- 2026-11-11: MySQL runs as a hidden background process bound to 127.0.0.1 instead of a Windows service (service install needs admin).
- 2026-11-11: `beds.taken_by_member_id` is UNIQUE so the database itself enforces one bed per person. Members are soft-removed (`removed_at`), never deleted.
- 2026-11-11: `audit_logs.trip_id` uses restrictOnDelete and the AuditLog model throws on update/delete (append-only). `error_logs` has no foreign keys on purpose so logging an error can never fail.
- 2026-11-11: Auth = random 40-char token in an encrypted HttpOnly, SameSite=Lax cookie named `lobby_{code}` with path `/t/{code}`; DB stores only sha256(token). Middleware looks up by (trip from URL, token hash), so a token from one trip cannot open another. Removed members get 403 on the next request.
- 2026-11-11: Rooms/beds are entered as plain text, one room per line (`Room 1: Window, Door`); limits 60 rooms, 10 beds/room, 200 beds total. Member names are unique per trip (case-insensitive, app-level check). Max 200 members per trip. POST /trips and /join throttled to 10/min/IP.
- 2026-11-11: Tests run on real MySQL (`thelobby_test`), not SQLite, because the locking behaviour must be real.
- 2026-11-11: Concurrency design: every bed action = DB::transaction(attempts 3) + lockForUpdate, locking the member row first, then bed rows. Retry covers MySQL deadlocks (proved with real parallel processes). Failures are returned as BedResult, never thrown, so the rejection audit row commits.
- 2026-11-11: Viewers cannot pick beds (watch only). A confirmed bed cannot be released (swaps are roadmap). Hold length is HOLD_SECONDS in .env (default 120).
- 2026-11-11: The screen polls GET /state every 2s; state is built from the DB each time with expired holds shown as free, so it is right even if the scheduler is not running. Countdown uses seconds_left (not timestamps) so wrong phone clocks do not matter.
- 2026-11-11: Rate limit for bed actions is 30/min per member (not per IP: friends share a Wi-Fi IP). Middleware priority list is adjusted so login runs before the limiter.
- 2026-11-11: MySQL starts with --mysqlx=OFF (no extra network port). It is a background process, not a service: after a reboot or app restart run scripts\start-mysql.ps1 (tests hang/fail with "connection refused" otherwise).
- 2026-11-11: demo:race starts one real PHP process per racer (Symfony Process; each waits for a shared start time, then calls BedService::grab). Chosen over HTTP requests because `php artisan serve` on Windows is single-threaded, which would hide the race. It creates temporary "Racer N (demo XXX)" members, verifies the result against the database, frees the bed and soft-removes the racers afterwards, and refuses to run in production. Its tests use DatabaseMigrations (real commits) because child processes cannot see an uncommitted test transaction.
- 2026-11-11: Invite = plain link (copy / WhatsApp / native share), not a QR code. Fewer dependencies, works on any phone.
- 2026-11-11: Audit policy: log every state change and every REFUSED or suspicious attempt (grab_rejected, confirm_rejected, release_rejected, action_refused, rate_limited). Not logged: harmless repeat of an action that is already true (double-tap on own held bed). rate_limited is one row per member per minute so spam cannot flood the table.
- 2026-11-11: Admin = ADMIN_KEY in .env, session login (not a key in the URL, which would leak into history and logs). Admin pages return 404 when the key is missing or under 16 characters. Error recorder stores route patterns and driver messages only, so no join codes, tokens or bound values land in the table.
- 2026-11-11: Removing a member frees their hold and their confirmed bed (a ghost with a bed would block it forever). Becoming a viewer frees only the open hold. One organiser per trip: cannot be removed, demoted, or created by role change. Organiser checks are done twice: route middleware (tidy 403 page) and inside MemberService with a fresh DB read (the real lock).
- 2026-11-11: Audit page is organiser-only, shows no IP addresses, pages by id (`?before=`) not page numbers because new rows keep arriving.
- 2026-11-11: AWS Free plan facts (checked against AWS docs this date): new accounts (created after 2025-07-15) get $100 credits, up to $100 more for activities (EC2, RDS, Lambda, Bedrock, Budgets: $20 each); the plan ends at 6 months or when credits run out, then the account CLOSES (data kept 90 days, reopen only by upgrading); you are not charged while on the Free plan. Free-plan EC2 types: t3.micro, t3.small, t4g.micro, t4g.small, c7i-flex.large, m7i-flex.large; RDS: db.t3.micro / db.t4g.micro (MySQL included). Joining AWS Organizations (also IAM Identity Center / Control Tower) auto-upgrades the account to Paid: never do it. Plan: EC2 t3.micro (x86, simpler than ARM), RDS db.t3.micro MySQL single-AZ, S3. Credits are consumed by usage, so tear down after the demo.
- 2026-11-11: Models use `$fillable` (mass-assignment protection); `Member::$hidden` includes token_hash.
- 2026-11-11: AWS storage design: one private S3 bucket in ap-south-1, Block Public Access on, SSE-S3 encryption, versioning off (so a delete really deletes), HTTPS-only bucket policy, lifecycle rule as a safety net (expire `trips/` after 30 days; known limit: counts from upload, not trip end). Files are only reachable through 60-second pre-signed links created after our app checks the member's role. Two IAM identities: a human admin user (console, MFA) and a code-only user `lobby-local-dev` whose policy allows only Put/Get/Delete on `trips/*` plus List with prefix `trips/*`. On EC2 an instance role replaces access keys. The `s3` disk has `throw => true` so failed uploads/deletes are never silent.
- 2026-11-11: Local Windows PHP needs a CA bundle for HTTPS (curl.se `cacert.pem`, checksum-verified, referenced by `curl.cainfo` and `openssl.cafile` in php.ini). This is a laptop-only fix; Linux on EC2 already trusts the system certificates. Verified against the real bucket: private, 60s links work and expire, writes outside `trips/` and listing the root are denied.
- 2026-11-11: composer.bat on Windows swallows the `^` in version constraints; edit composer.json by hand for caret ranges.
- 2026-11-11: Vault design: files are only ever reached through our app. The page links to `/vault/{id}/open`, which re-checks membership and trip state on every click, audits it, then redirects to a pre-signed S3 link valid for 60 seconds (so a page left open for an hour never holds a dead or long-lived link). Keys are `trips/{trip_id}/{random}`; original names live only in the database. Upload order is S3 first, database second (no DB lock held during the network call); if the database step fails or the trip ended meanwhile, the stored bytes are deleted again.
- 2026-11-11: Self-destruct is two paths into one retry-safe function (`VaultService::purgeTrip`): organiser "End trip now" and the `vault:purge` job (every 5 minutes; a trip is over the day after `ends_on`, UTC). A trip is flagged `vault_purged_at` only when every file AND the folder sweep succeeded; otherwise the next run finishes it. Audit rows are never deleted; the rows in `vault_files` stay with `deleted_at` set.
- 2026-11-11: Limits: 10 MB per file, 40 files per trip, types pdf/jpg/png/webp/heic/heif (content checked, not just the name). HEIC kept as-is, no image library added. Vault actions limited to 20 per minute per member.
- 2026-11-11: Deploy design: one Ubuntu 24.04 EC2 (t3.micro) running Nginx + PHP-FPM 8.4 (ondrej PHP repo; Ubuntu's own PHP is below the 8.4.27 minimum), database on RDS MySQL 8.4 (single-AZ, private, TLS with the AWS CA bundle, `MYSQL_ATTR_SSL_CA`), files in the private S3 bucket reached through the EC2 IAM role (no keys on the server). The app uses its own limited MySQL user, not the RDS master. Scripts live in `deploy/`. Only index.php may execute as PHP; hidden files are denied; security groups: web = SSH from the owner's IP only + 80/443 public, db = 3306 from the web group only.
- 2026-11-11: Correction: PHP on the server comes from `packages.sury.org` (the PHP maintainer's own apt repository, key pinned with signed-by), not the Launchpad PPA, because Launchpad hosts are unreachable from the EC2 instance. Offers 8.4.27 on Ubuntu 24.04, which meets the security minimum; `setup-server.sh` refuses to continue on anything older.
